# 无设计输入时的默认效果 UI

只在用户没有给出设计要求、工程也没有现有效果面板、设计系统或可复用组件时采用本规范。图标、字号、圆角和动效可以继续跟随客户工程；颜色、材质、描边、分隔线和阴影必须统一映射到本文的一套主题 token，不能由各面板自行选择。工程没有可复用主题 token 时，必须使用本文默认主题。

## 共享底部操作栏

- 使用一个共享底栏容器承载所有顶层入口；不要为每个入口分别添加带横向内边距的胶囊背景，否则模块增加后会挤压标题并造成换行。
- 让每个入口等宽伸展并共享可用宽度。入口之间使用零或短间距，背景、描边和阴影放在父容器上。
- 效果入口采用纵向“图标在上、短标题在下”。标题固定单行，允许适度收紧或缩小，但不能依赖自动换行；图标和标题整体保持至少 `44 pt` 的可点击高度。
- 在最小支持设备宽度上按“当前入口 + 用户已明确的近期入口”计算容量。默认基线至少容纳五个短标题入口；不要为了证明容量而向生产界面加入无功能占位按钮。
- 把入口视图抽成与具体效果无关的通用组件，使美颜、美妆、滤镜、道具和后续录制入口复用同一布局。录制只复用视图，不并入 NVE 效果状态、面板枚举或清除语义。
- 存在四个效果入口和一个录制入口时，录制只显示较大的状态图标，不显示底部文字；仍占用等宽槽位并保留至少 `44 pt` 触控区域，图标放大不能挤压相邻入口。
- 不规定任何底栏入口的默认先后顺序，也不强制录制位于中间；跟随客户导航语义或实现时的稳定顺序即可。不得为了未声明的外部基线强制重排已有入口。
- 超过五项、标题本地化后明显变长，或入口宽度会低于可用触控范围时，优先复用客户的横向滚动、更多菜单或分组方案；不要继续压缩到不可读、不可点。

SwiftUI 实现时，父级可使用零间距或短间距的 `HStack`，每个 `Button` 和其 label 使用 `frame(maxWidth: .infinity)`；label 内使用 `VStack`、`lineLimit(1)`、`minimumScaleFactor` 和 `allowsTightening`，共享材质或背景只应用到父级。

UIKit 实现时，优先使用横向 `UIStackView` 的 `fillEqually` 分布；入口内部纵向排列图标和单行 label，设置 `numberOfLines = 1`，并按客户规范启用收紧或最小字号。不要用每个标题的 intrinsic width 决定顶层入口宽度。

## 面板与状态

- 底部入口栏与编辑面板互斥：入口栏收起后展示当前面板；默认 UI 只通过点击面板外空白区域关闭面板并恢复入口栏，不在面板内部放置专用收起或关闭按钮。
- 采用已验证的底部容器结构：使用同一个底部容器在共享入口栏和当前编辑面板之间切换，再由容器统一施加外部水平与底部间距；不要让每个入口或面板各自决定屏幕边缘间距。
- 底部入口栏和展开后的编辑面板相对底部安全区使用同一个外部底部间距。优先复用客户工程的 spacing token；没有现成 token 时定义一个共享局部常量，默认基线取 `10 pt`。不得为入口栏和各效果面板分别硬编码不同数值。不要忽略底部安全区，也不要在已有安全区 inset 上重复叠加间距；在带 Home Indicator 的设备上，距物理屏幕底部应为系统安全区加该共享间距。
- 每个顶层效果模块保留独立入口和独立面板。展开、收起或切换面板不能清除已应用效果、当前选项、强度或已安装 package ID。
- 相机切换、授权/初始化错误和录制状态独立于效果面板。不要为了容纳入口把这些全局状态塞入效果分类 tab。
- 相机切换按钮默认放在预览右上角；录制期间没有明确的格式迁移规则时禁用。录制完成提示默认约 `2–3 秒` 后自动消失，不能常驻遮挡预览。
- 给共享底栏、每个入口、面板和收起层添加稳定 accessibility identifier；入口的 identifier 继续使用 `nve.<feature>.entry`，录制沿用客户录制命名规范。

## 默认主题

主题选择是原子决策：用户明确主题优先，其次把客户工程已有语义颜色完整映射到下表；两者都不存在时使用固定的深色预览覆盖主题。不能让部分面板使用客户颜色、其他面板使用默认颜色，也不能为美颜、美妆、滤镜、道具分别选择强调色。

默认实现必须声明唯一共享主题类型 `NVEEffectTheme` 和契约标识 `nve.default-theme.v1`。SwiftUI 通过同一个 environment value 或父级注入实例读取；UIKit 通过同一个不可变主题实例或统一 appearance 配置读取。共享底栏、全部编辑面板、卡片、slider、Toggle、分隔线、状态提示和相机/录制控件只能引用该主题，不得在各组件文件中再次硬编码主题颜色或透明度，也不得每个面板创建一份可独立修改的主题。

默认深色主题使用 sRGB 颜色；`alpha` 是合成透明度：

| Token | 默认值 | 统一用途 |
| --- | --- | --- |
| `canvas` | `#000000`, alpha `1.00` | 预览不可用、权限页或加载阶段的底色 |
| `surfaceMaterial` | 系统深色 ultra-thin material；不可用时 `#000000`, alpha `0.74` | 底栏和所有编辑面板的共同材质层 |
| `barOverlay` | `#000000`, alpha `0.48` | 共享底栏材质上的覆盖层 |
| `panelOverlayTop` / `panelOverlayBottom` | `#000000`, alpha `0.36` / `0.62` | 所有编辑面板共用的纵向覆盖层 |
| `containerBorder` | `#FFFFFF`, alpha `0.20` | 底栏和全部面板的外边框 |
| `divider` | `#FFFFFF`, alpha `0.16` | 面板内分隔线 |
| `textPrimary` | `#FFFFFF`, alpha `1.00` | 数值、选中项文字和主要提示 |
| `textSecondary` | `#FFFFFF`, alpha `0.68` | 操作说明、素材提示 |
| `textMuted` | `#FFFFFF`, alpha `0.58` | 未选中 tab 和弱化文字 |
| `iconSecondary` | `#FFFFFF`, alpha `0.82` | 未选中图标和无封面时的本地图标 |
| `itemFill` / `itemBorder` | `#FFFFFF`, alpha `0.08` / `0.12` | 未选中卡片背景和边框 |
| `accent` | iOS `systemPink`，sRGB 回退 `#FF2D55` | 所有面板的选中 tab、选中边框、slider 和 Toggle |
| `accentFill` | `accent`, alpha `0.13` | 所有面板的选中卡片或选中分类背景 |
| `disabledOpacity` | `0.36` | 禁用参数控件的整体透明度 |
| `containerShadow` | `#000000`, alpha `0.28` | 底栏和面板的统一阴影颜色 |
| `statusNeutral` | `#000000`, alpha `0.60` | 准备中、保存中等中性状态背景 |
| `danger` / `dangerFill` | iOS `systemRed`、`#FF3B30` / alpha `0.82` | 录制符号和错误状态；普通选中态不得使用 |
| `successFill` | iOS `systemGreen`、`#34C759`, alpha `0.72` | 完成状态；普通选中态不得使用 |
| `cameraSurface` / `cameraBorder` | `#000000`, alpha `0.55` / `#FFFFFF`, alpha `0.75` | 右上角相机切换按钮 |

状态映射固定如下：

- 共享底栏使用 `surfaceMaterial + barOverlay + containerBorder + containerShadow`。
- 所有编辑面板使用同一组 `surfaceMaterial + panelOverlayTop/panelOverlayBottom + containerBorder + containerShadow`，不得按模块改变背景或边框。
- 选中 tab、选中素材边框、slider、Toggle 统一使用 `accent`；选中卡片背景统一使用 `accentFill`。美颜、美妆、滤镜和道具不得各自使用不同主题色。
- 未选中卡片统一使用 `itemFill + itemBorder`；主、次、弱化文字分别使用 `textPrimary`、`textSecondary`、`textMuted`。
- 分隔线统一使用 `divider`。禁用状态保留原色并整体应用 `disabledOpacity`，不要另选灰色。
- 红色只用于录制和错误，绿色只用于完成状态；不能把录制红色、错误红色或成功绿色当作任一效果模块的选中色。

如果客户工程已有完整主题，允许替换默认值，但必须一次性映射全部 token，并让所有模块共享同一个映射实例。缺少某个客户 token 时从本表补齐到同一个实例；不得在面板内部临时取色。交付报告记录使用“客户主题映射”还是 `nve.default-theme.v1`。

## 固定控件与层级

采用本默认 UI 时，以下是结构验收基线。颜色、材质、描边和阴影执行“默认主题”；图标、字号、圆角、动画和卡片精确尺寸可以跟随客户工程，但不得省略表中的必需控件，也不得增加表中明确禁止的常驻控件。加载、错误、空提示等条件式状态不出现时不占位。

| 区域 | 必需控件与自上而下层级 | 条件式控件 | 默认禁止 |
| --- | --- | --- | --- |
| 预览全局层 | 主要预览；右上角相机切换；独立的效果准备/错误状态区域 | 请求包含录制时增加独立录制状态提示；完成提示约 `2–3 秒` 后消失 | 把相机切换、效果错误或录制状态放进任一效果分类 tab |
| 共享底栏 | 每个已请求效果各一个独立入口；效果入口为图标在上、单行标题在下 | 请求录制时增加一个无标题、等宽槽位的录制按钮，不限定所在位置 | 每入口独立胶囊背景；无功能占位入口；录制文字标题 |
| 美颜面板 | 顶部“美肤、美型、微整形”纯文字功能域 tab；分隔；横向参数卡片列表，卡片为封面在上、单行参数名在下；底部控制行依次为数值、slider、重置、启用开关 | 只接入部分美颜范围时只保留已请求功能域；功能域关闭时 slider 禁用 | 常驻说明标题；面板内关闭/收起按钮；把三个功能域拆成顶层效果入口 |
| 完整美妆面板 | 顶部十类横向分类；分隔；横向单选素材卡片列表，每类“无”在第一项 | loading/error 使用目标卡片状态或共享效果状态区域，消失后不占位 | 默认强度 slider、启用开关、重置按钮、额外常驻说明标题、面板内关闭/收起按钮 |
| 滤镜面板 | 顶部简短操作说明；横向单选素材卡片列表，“无”在第一项 | 选中具体滤镜后，在列表下增加分隔和“数值 + slider”强度行；选“无”后整行移除 | 启用开关、重置按钮、常驻禁用 slider、面板内关闭/收起按钮 |
| 道具面板 | 顶部简短操作说明；横向单选素材卡片列表，“无”在第一项 | 当前素材返回非空交互提示时，在列表下增加分隔和提示行；提示为空时整行移除；loading/error 使用目标卡片状态或共享效果状态区域 | 强度 slider、启用开关、重置按钮、伪造的提示占位、面板内关闭/收起按钮 |
| 录制 | 共享底栏中的单个无标题录制按钮；idle/recording 使用可区分的录制/停止符号 | starting、stopping、saving 期间禁用重复点击；完成或失败通过独立录制状态提示反馈 | 独立录制编辑面板、录制清除语义、把录制加入效果状态或效果面板枚举 |

“简短操作说明”表达真实动作即可，可以本地化或按客户文案调整；滤镜不要使用“无滤镜”等静态状态冒充说明，道具不要把素材提示写成常驻说明。结构一致性只要求上述控件与层级，不要求逐像素复刻。

默认实现固定使用以下稳定标识：

```text
nve.effect.bottom-bar
nve.effect.dismiss
nve.effect.status
nve.beauty.entry / panel / parameter.select / intensity / clear / enable
nve.makeup.entry / panel / category.<id> / option.<id> / clear
nve.filter.entry / panel / parameter.select / option.<id> / intensity / clear
nve.prop.entry / panel / parameter.select / option.<id> / clear / prompt
camera.switch
camera.record
camera.record.status
```

`loading` 和 `error` 可以附着在目标卡片或复用 `nve.effect.status`，不是必须新增的常驻面板行。采用默认命名时，共享底栏也兼容既有 `camera.bottom-action-bar`；静态验证接受这两个名称。

## 完整美妆面板

用户要求完整美妆且没有提供设计、工程也没有可复用效果面板时，使用以下固定信息架构：

- 共享底部操作栏提供独立“美妆”入口；进入后用同一个底部容器替换入口栏，不覆盖主要预览区域。
- 面板顶部是横向分类栏，顺序固定为“妆容、口红、眼影、眉毛、睫毛、眼线、腮红、提亮、修容、美瞳”。“妆容”代表组合妆容并固定在第一项。
- 分类栏与选项区之间使用分隔线或工程现有等价分组样式。选项区是横向单选素材卡片，每个分类的“无”固定在第一项。
- 当前分类和当前素材统一使用主题 `accent`/`accentFill`；点击素材立即应用。默认不显示强度 slider，只有产品明确要求时增加。
- 面板只通过点击面板外空白区域关闭；切换分类、切换素材、关闭面板或切换其他顶层面板均不清除已应用美妆。
- UI 自动化使用 `nve.makeup.entry`、`nve.makeup.panel`、`nve.makeup.category.<id>`、`nve.makeup.option.<id>` 和 `nve.makeup.clear` 等稳定 accessibility identifier。条件式 loading/error 可以附着在目标卡片或使用共享 `nve.effect.status`，不得因此增加常驻行。

本节就是完整美妆默认结构的自包含事实来源。颜色、材质、边框和状态色统一使用“默认主题”；图标、字体、圆角和素材卡片精确尺寸可以继续跟随客户工程。

## 布局验收

- 在项目支持的最窄设备宽度验证：所有入口等宽，短标题保持单行，没有裁切、重叠或越界，且每项可点击。
- 至少检查默认 Dynamic Type 和一个更大字号；放大后仍不得出现两行标题。无法满足时使用客户的滚动或更多菜单方案。
- 若用户已声明近期会增加第 5 个入口，使用 Preview、测试 fixture 或临时调试数据验证五项布局，然后移除非功能占位数据；不要只验证当前四项。
- 五项包含录制时，验证录制入口无标题、图标视觉上更突出且不与相邻入口重叠；完成提示在规定时间后消失，不断言录制所在位置。
- 分别展开每个默认效果面板，验证入口栏与所有面板复用同一底部容器和间距来源，且面板内不存在专用收起或关闭按钮；工程没有 spacing token 时验证共享底部间距采用 `10 pt` 默认基线。
- 按“固定控件与层级”逐项断言必需控件存在、条件式控件按状态出现或移除、默认禁止控件不存在；不对任何底栏入口的先后顺序做断言。
- 验证共享底栏与每个面板都读取同一个 `NVEEffectTheme` 实例或同一客户主题映射；背景、边框、分隔线、主/次文字、选中/未选中卡片、slider、Toggle 和状态色符合固定 token 映射。不得以每个面板“看起来接近”代替共享主题来源证据。
- 在明亮和暗色预览输入上检查文字、图标和选中边框可辨识；颜色验收比较语义 token 和解析后的组件属性，不要求全屏逐像素完全相等。
- UI 自动化继续验证入口可点击和面板状态；换行、裁切与等宽优先用项目已有 snapshot、Preview 或布局断言验证，不依赖坐标点击。
